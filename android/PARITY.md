# Android feature parity and verification

Android uses the original app's Home, Search, Library, Now Playing and Settings destinations. Native audio and YouTube have different playback capabilities. This table describes the implementation shipped in the Android source.

| iOS feature | Android behavior | Verification |
| --- | --- | --- |
| InnerTube music and video search | YouTube Data API search for videos, channels and playlists. Channels and playlists drill down to videos. Paste a YouTube link without an API key. Archive search covers songs, releases, creators and music videos. | YouTube response fixtures, link parsing, Archive query construction, live Archive browsing and an emulator link-opening check. Live credentialed YouTube search requires a registered project. |
| Search history and cache | Room keeps the latest 20 terms, with clear and reuse actions. Archive release search has a bounded session cache plus HTTP caching where permitted. | JVM tests exercise artist queries, malformed responses and HTTP errors. |
| Home and recommendations | Popular licensed releases, local Listen Again and a related-artist shelf when available. Connected account playlists open from Home. | Popular releases and Listen Again observed on device. Personal YouTube Music mixes and remote listening history are unavailable through the chosen integration. |
| Albums and artists | Netlabel releases open ordered audio-file lists. Creator search groups matching releases. YouTube channels and playlists use public platform identifiers. Archive video results open the item's page. | An Archive release opened with 15 playable entries. Song search checks track metadata in the first six matching releases and returns related releases for further browsing. |
| Native playback | Media3 service, focus/noisy-device handling, media notification, lock-screen and headset commands, seek, previous/next, Play All, Shuffle All, repeat, queue move/remove/append. Audio quality selects a file variant when opening a release. | Device tests exercised an actual WAV through MediaController, seek, shuffle, repeat, reorder and removal. Live Archive stream and background media session verified. Physical Bluetooth/headset behavior still needs a hardware check. |
| YouTube playback | Eligible videos use the official visible embedded player. Saved YouTube entries can form a foreground video queue. Open in YouTube is available if embedding fails. Audio-only background playback and offline downloads apply to native audio. | Player screen opened from a pasted video link. Successful YouTube media delivery depends on embeddability, connectivity and WebView. Credentialed playback has not been certified. |
| Native queue persistence | Store track IDs, index, position, repeat and shuffle. Restore paused after process loss. Position checkpoints run during playback and on player events. | Restored the previous recording and paused mini-player after force-stop and cold launch. Shuffle mode persists; Media3 may generate a new shuffle traversal after process recreation. |
| Local library and playlists | System file picker with persisted grants, embedded audio tags/artwork, favorites, named ordered playlists, rename, delete, add/remove tracks. Tracks from a played native queue enter the library. | Room and instrumentation tests cover changes, duplicate adds, deletion and replayed synchronization. Re-importing an identical local file restores its grant on another phone. |
| Recents and listening statistics | Count native playback starts and elapsed playing time per track and installation. Aggregate recent tracks, most-played songs, artists and total listening time. | Database and device tests. YouTube's embedded player manages its own playback history. |
| Downloads and storage | WorkManager, connected-network constraint, progress, cancellation, retries, size limits, atomic file publication, startup reconciliation, individual removal and clear-all. | Downloaded an 8,229,144-byte recording, disabled Wi-Fi and mobile data, restarted, and observed playback position advancing. Cancellation and quota exhaustion still need extended device testing. |
| Account | Optional Google Play services read-only authorization, account playlists, local sign-out, memory-only OAuth tokens and Keystore-encrypted user API key. Guest access works without credentials. | Encrypted key persistence exercised on device. Live OAuth consent, quota handling and private playlist access need a registered client and account. |
| Direct library sync | Android NSD discovers an explicitly hosting peer. Mutual TLS, matching certificate codes confirmed on both phones, versioned bounded messages and Room transactions protect the exchange. | Instrumentation starts two peers with separate databases on an emulator, discovers the host, compares codes, confirms and checks both libraries. Two physical devices on a real Wi-Fi network remain a field test. |
| iOS interoperability | Settings imports and exports the original playlist JSON array (`id`, `name`, `songs[].videoId`). Import unions members by ID. Export includes YouTube entries and playlist names. | Android round-trip test uses an iOS-shaped fixture. The iOS LAN service uses automatic unpaired HTTP and incompatible stats, so cross-platform LAN sync is unavailable. No iOS device was exercised. |
| Appearance and navigation | Original launcher and transport artwork, red/near-black or light palette, system theme, artwork backdrop, mini-player, full player, configurable tiles, transitions, speed, screen-awake and bitrate settings. | Now Playing inspected on an emulator. ## Sync and source limits

Compare all five fingerprint groups on both screens before selecting **Codes match**. Only metadata crosses the network. Each phone retains its audio files, file permissions, API key and account credentials. A valid Android snapshot may be up to 8 MiB and 20,000 songs. The latest edit wins for an entire playlist or favorite, with a deterministic tie-break and playlist deletion markers. Concurrent edits to the same playlist can overwrite one another. Listening counters take the maximum per track and installation, so repeated exchanges do not add the same plays twice.

The YouTube Data API returns a page of up to 50 public search, channel or playlist entries per browse action. The account playlist listing requests additional pages up to 1,000 playlists. Foreground video queues can contain the selected video and up to 50 following videos. For mixed playlists, selecting a recording queues entries supported by the same player. A YouTube subscription does not carry native background or download entitlements into this app.

Internet Archive downloads require an item-level recognized Creative Commons license or public-domain declaration, an accessible file and a supported audio format. Item and license links are available in song menus. A provider's catalog, format selection, network response or removed item can affect availability.

## Reproduce the checks

From `android/`, run `./gradlew testDebugUnitTest lintDebug assembleDebug`. With a disposable emulator running, also run `./gradlew connectedDebugAndroidTest`. The instrumentation suite uses temporary databases and exercises media playback, pairing and local settings. Use a test installation because Android's connected test tooling can uninstall the app after a run. HTML reports are generated under `app/build/reports/`. The hosted workflow builds a debug-signed artifact and uploads its reports.


Android 17 verification on 24 November 2026 passed five device tests. Connect Google account reached the Google Play services sign-in screen on an emulator with no configured account. End-to-end consent and private-playlist loading still require a registered OAuth client and an authorized test account. The revised debug build passed nine JVM tests and lint with zero errors.
